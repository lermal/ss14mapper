# Управление гайдами и FAQ

В меню аккаунта выберите **«Гайды и FAQ…»**. Вы откроете панель
`/admin/content/?lang=ru` в новой вкладке и сохраните карту в редакторе.
Для доступа добавьте GitHub ID администратора в `MAINTAINER_GITHUB_IDS` на API.

## Работа с материалами

1. Выберите раздел и язык, нажмите «Новый гайд» или «Новый вопрос».
2. Введите заголовок, адрес латиницей и текст в Markdown. Для FAQ укажите вопрос
   в заголовке, ответ в тексте. Добавляйте форматирование и изображения кнопками
   над текстом. Нажмите «Предпросмотр», чтобы проверить результат.
3. Нажмите «Сохранить черновик», чтобы сохранить работу, или «Опубликовать»,
   чтобы показать материал на сайте. После правок опубликованного материала
   нажмите «Опубликовать изменения». До этого читатели увидят прежнюю версию.
4. Меняйте порядок кнопками «Выше» и «Ниже» в списке. Перед перестановкой
   сбросьте поиск и фильтр статуса. Для каждого раздела и языка задайте свой порядок.
5. Нажмите «Снять с публикации», чтобы убрать материал с сайта и из sitemap,
   сохранив черновик. Через «Удалить» вы удалите черновик и публикацию.

Напишите русский и английский тексты. Укажите у перевода тот же адрес и
опубликуйте обе версии, чтобы читатели могли переключать язык.
Выберите адрес до публикации: после неё изменить его нельзя.
В поле «Категория» укажите подпись для списка материалов.

Загружайте изображения в PNG, JPEG или WebP до 5 МБ и 6000 × 6000 пикселей.
Любой посетитель со ссылкой сможет открыть файл с момента загрузки,
в том числе до публикации текста. Используйте изображения для открытого доступа.

## Подключение к рабочему сайту

Обновите **оба проекта**: `ss14mapper` и `ss14mapper-api`.

1. Обновите код API и задайте `MAPPER_SITE_URL=https://ss14mapper.forged.by` в его окружении.
   Сохраните настройки авторизации, CORS и `MAINTAINER_GITHUB_IDS`.
2. В каталоге API выполните:

   ```sh
   php artisan migrate --force
   php artisan content:import-guide
   php artisan config:cache
   php artisan view:clear
   ```

   Через `content:import-guide` вы перенесёте английский и русский гайд в материалы
   `getting-started` и опубликуете их. Повторный запуск пропускает материалы с этим адресом
   и сохраняет ваши правки. Пропустите импорт, если хотите начать с пустого
   списка. Пустые разделы имеют метатег `noindex`.
3. Соберите фронтенд `npm run build` с текущим `VITE_API_URL` и опубликуйте
   весь `dist/`, включая `admin/content/index.html` и `content.css`.
4. В nginx замените `public-discovery-server.conf` на `tools/nginx/content-server.conf`.
   Сохраните `public-discovery-http.conf` в `http{}`.
   Скопируйте `content-upstream-http.conf.example`, укажите HTTP-адрес и Host
   nginx/Apache-сервера, который обслуживает Laravel, и подключите файл в `http{}`.
   Не указывайте здесь сокет PHP-FPM или адрес фронтенда: с адресом фронтенда
   вы получите цикл запросов.
   Сохраните настройки HTTPS, API, packs и защитные заголовки. Проверьте `nginx -t`
   перед перезагрузкой. Для соединения с API по HTTPS настройте HTTPS upstream,
   SNI и проверку сертификата.
5. Направьте `/guide/*`, `/faq/*`, `/content-media/*` и `/sitemap.xml` в API.
   Для `/admin/content/` на домене фронтенда отдавайте файл из `dist/`.
   Для административных запросов используйте текущий `VITE_API_URL`.
6. Отключите кеширование HTML разделов, sitemap и админки в Cloudflare.
   После переключения очистите кеш этих адресов. Для публичного HTML и sitemap
   API возвращает заголовок `Cache-Control: no-cache`.
7. Откройте `/guide/`, `/guide/ru/`, `/faq/ru/` и создайте черновик через панель.
   После импорта гайдов запустите `npm run check-site -- https://ss14mapper.forged.by`.
   Проверьте, что в sitemap есть опубликованные статьи и нет черновиков.

На API и его прокси разрешите тело запроса размером от 6 МБ. В PHP задайте
`upload_max_filesize` от 5 МБ и `post_max_size` больше этого значения.
Делайте резервные копии базы и `storage/app/private/content-images`
(либо каталога настроенного диска `local`). После удаления материала изображения остаются
на диске: вы можете использовать их в других статьях.

## Локальная разработка

Используйте тестовую базу API. Запустите Vite с прокси:

```sh
VITE_API_URL=/api SS14MAPPER_DEV_API=http://127.0.0.1:8771 npm run dev -- --host 127.0.0.1 --port 8772
```

Запустите API на порту 8771. В его окружении укажите адрес фронтенда с портом 8772
в `MAPPER_SITE_URL`, `FRONTEND_URLS` и `SANCTUM_STATEFUL_DOMAINS`. Настройте cookie
и OAuth callback для локального входа. Пробросьте 8772 через VS Code; используйте
одинаковый hostname в браузере и конфигурации. Этот прокси доступен в режиме разработки.
